# تمرین ۲: جستجوی مدل خودرو (از صفر)

یه کامپوننت جستجو رو **سه بار** پیاده می‌کنی: با `fetch` خالی، با `axios`، و با React Query.
هر تب تو صفحه یکی از این سه فایله: `SearchFetch.tsx`، `SearchAxios.tsx`، `SearchQuery.tsx`.

## اجرا
```bash
npm install
npm run dev
```

## API
`GET /api/models?q=<عبارت>`

```ts
// جواب موفق
{ items: CarModel[], total: number }   // تایپ‌ها تو src/types.ts
```

رفتارهایی که عمداً توش گذاشته شده:
- **هر چی عبارت کوتاه‌تر، جواب کندتر.** «پ» حدود ۱.۵ ثانیه طول می‌کشه و «پژو» حدود ۶۰۰ms. یعنی اگه مراقب نباشی، جواب قدیمی روی جواب جدید می‌شینه.
- اگه عبارت شامل **«خطا»** یا **error** باشه، ۵۰۰ برمی‌گردونه.
- `q` خالی، **همه‌ی ۲۰۵۰ مدل** رو برمی‌گردونه (برای تست virtualization).
- هر درخواست و هر **لغو** تو ترمینالِ `npm run dev` لاگ می‌شه.

## نیازمندی‌ها

### مرحله‌ی ۱: هسته (⏱️ ۴۵ دقیقه، فقط `SearchFetch.tsx`)
1. یه input که کاربر توش تایپ می‌کنه.
2. درخواست فقط بعد از **۳۰۰ms** مکث در تایپ زده بشه (`useDebounce` رو خودت بنویس).
3. برای عبارت کمتر از ۲ کاراکتر درخواست نزن.
4. چهار حالت رو نشون بده: **loading**، **error** (با دکمه‌ی تلاش مجدد)، **نتیجه‌ای پیدا نشد**، و **لیست نتیجه‌ها**.
5. درخواست قبلی با `AbortController` **لغو** بشه. لغو شدن نباید پیام خطا نشون بده.
6. تعداد نتیجه‌ها رو نشون بده («۷۵ نتیجه»).

**چطور تست کنی که درست کار می‌کنه:**
- آروم تایپ کن «پ»، مکث، «ژ»، مکث، «و». تو تب Network باید درخواست‌های قبلی `(canceled)` بشن و تو ترمینال «لغو شد» ببینی.
- هیچ‌وقت نباید نتیجه‌ی «پ» بعد از نتیجه‌ی «پژو» روی صفحه بیاد.
- «خطا» رو تایپ کن. بعد پاکش کن و یه چیز درست تایپ کن. پیام خطا باید بره.

### مرحله‌ی ۲: axios (⏱️ ۲۰ دقیقه، `SearchAxios.tsx`)
همون رفتار، با axios. به این‌ها دقت کن:
- `params` به جای ساختن دستی query string
- تشخیص لغو با `axios.isCancel`
- axios برای ۵۰۰ خودش reject می‌کنه؛ `fetch` چی؟

### مرحله‌ی ۳: React Query (⏱️ ۲۰ دقیقه، `SearchQuery.tsx`)
- `queryKey` و `enabled`
- `signal` رو از `queryFn` به axios یا fetch پاس بده
- موقع تایپ عبارت جدید، نتیجه‌ی قبلی رو نگه دار تا صفحه نپره (`placeholderData`)
- فرق `isLoading` و `isFetching` رو تو UI نشون بده

بعد از این مرحله، سه تا فایل رو کنار هم بذار و ببین چند خط کد کمتر شد و **چی** حذف شد.

### مرحله‌ی ۴: کیبورد و دسترس‌پذیری (⏱️ ۳۰ دقیقه، روی یکی از سه تا)
- کلیدهای ↑ و ↓ بین نتیجه‌ها حرکت کنن، Enter انتخاب کنه، Escape لیست رو ببنده.
- آیتم فعال همیشه تو دید باشه (`scrollIntoView`).
- `role="combobox"`، `role="listbox"`، `role="option"`، `aria-activedescendant`.

### مرحله‌ی ۵: virtualization (⏱️ ۴۵ دقیقه)
input رو خالی کن که هر ۲۰۵۰ مدل بیاد.
- اول تو React Profiler یا تب Performance ببین رندر ۲۰۵۰ تا `<li>` چقدر طول می‌کشه.
- **یه بار با دست** پیاده کن: ارتفاع ثابت هر ردیف، محاسبه‌ی اولین و آخرین ردیف قابل‌دیدن از روی `scrollTop`، یه container با ارتفاع کل، و `transform: translateY`.
- **بعد با `@tanstack/react-virtual`** (از قبل نصبه).
- حرکت با کیبورد هنوز باید کار کنه. اینجا `scrollIntoView` دیگه جواب نمی‌ده. چرا؟

## قوانین
- تایمر بذار. بلند فکر کن.
- مرحله‌ی ۱ **بدون AI**. از مرحله‌ی ۲ به بعد می‌تونی از AI استفاده کنی، ولی هر خطش رو باید بتونی توضیح بدی.
- بعد از هر مرحله، کد رو بفرست تا بررسی بشه.
