# تمرین ۵: شبیه‌سازی سوم (سپر، پنل بیمه‌گذار)

⏱️ **دقیقاً ۲ ساعت.** با تایمر.

تازه به تیم پنل بیمه‌گذار «سپر» اضافه شدی. ۱۶ تیکت باز تو `TICKETS.md` هست. **قرار نیست همه‌ش تموم بشه.**

## اجرا
```bash
npm install
npm run dev          # محیط توسعه: http://localhost:5173
npm run prod         # build + اجرای نسخه‌ی production: http://localhost:4173
```
- کاربرهای آزمایشی: `mina` / `1234` و `reza` / `1234`
- React Query Devtools نصبه (گوشه‌ی پایین-چپ).
- **dev و prod دو تا بک‌اند جدا دارن.** دیتای یکی تو اون یکی نیست، و با ری‌استارت سرور دیتا ریست می‌شه.
- **شبیه‌سازی دیپلوی:** `VITE_APP_VERSION` رو تو `.env` عوض کن و دوباره `npm run prod` بزن.
- اگه محیط prod قاطی شد: DevTools ← Application ← Storage ← **Clear site data**. ولی اول بفهم چرا قاطی شد.

## درباره‌ی پروژه
- صفحه‌ها: ورود (`/login`)، داشبورد (`/`)، بیمه‌نامه‌ها (`/policies`)، جزئیات (`/policies/:id`)، بیمه‌ی مسافرتی (`/travel`)
- React Query، axios با interceptor، React Hook Form و Zod، react-router
- **API:** `mock-api.ts` بک‌اند تیم دیگه‌ست: **تغییرش نده.**
  - احراز هویت: access token **۴۵ ثانیه** اعتبار داره، و refresh token **یک‌بارمصرفه**. استفاده‌ی دوباره از یه refresh token کل نشست رو باطل می‌کنه.
  - همه‌ی مبالغ به ریال‌ان. تاریخ‌ها رشته‌ی `YYYY-MM-DD`، بدون ساعت.
  - لاگ درخواست‌ها تو ترمینال `npm run dev` چاپ می‌شه.

## قوانین
- AI مجازه؛ هر خطش رو باید بتونی توضیح بدی.
- برای هر تیکت: **بازتولید ← علت ← فیکس ← دوباره انجام دادن مراحل تیکت.**

## این بار، این‌ها رو حتماً رعایت کن
1. **۱۰ دقیقه‌ی اول کد ننویس.** تیکت‌ها رو بخون، برای هر کدوم یه فرضیه‌ی یک‌خطی بنویس، و ببین کدوم‌ها **یه ریشه‌ی مشترک** دارن.
2. **اولویت‌بندی با دلیل.** امنیت و داده‌ی مشتری، پول، و هر چیزی که جلوی کار یا تست بقیه رو می‌گیره.
3. **بعد از هر فیکس، مراحل همون تیکت رو دوباره انجام بده، و یه مسیر سالم نزدیکش رو هم.**
4. **اول کنسول، Network و ترمینال سرور رو نگاه کن.** Application tab هم وجود داره.
5. **قبل از تحویل `npm run typecheck`.** و `console.log` اضافه نذار.
6. **۱۰ دقیقه‌ی آخر فقط `REPORT.md`،** با شماره‌ی دقیق تیکت‌ها (SPR-3xx) و ستون «چطور تست کردم».
