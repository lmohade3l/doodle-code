# تمرین ۳: شبیه‌سازی مصاحبه (بیمه‌یاب)

⏱️ **دقیقاً ۲ ساعت.** تایمر بذار و سر ۲ ساعت دست نگه دار، حتی اگه وسط یه تیکتی.

تازه به تیم «بیمه‌یاب» اضافه شدی. این کدبیس رو قبلاً ندیدی. ۱۵ تا تیکت باز تو `TICKETS.md` هست.

**قرار نیست همه‌ش رو تموم کنی.** تعداد تیکت‌ها عمداً بیشتر از دو ساعت کاره.

## اجرا
```bash
npm install
npm run dev
```
React Query Devtools نصبه (دکمه‌ش گوشه‌ی بالا-چپ صفحه‌ست).

## قوانین
- **AI مجازه**، مثل خود مصاحبه. ولی هر خطی که AI می‌نویسه رو باید بتونی توضیح بدی.
- `mock-api.ts` بک‌انده و مال یه تیم دیگه‌ست: **تغییرش نده.** اگه بک‌اند رفتار عجیبی داره، سمت فرانت باهاش کنار بیا (و تو گزارشت بنویس که باید به تیم بک‌اند گفته بشه).
- برای هر تیکت: **بازتولید ← علت ← فیکس ← تست دوباره.**
- بلند فکر کن، یا فکرت رو یادداشت کن.

## روش پیشنهادی
1. **۱۰ دقیقه‌ی اول کد ننویس.** اپ رو اجرا کن و باهاش کار کن. ساختار پوشه‌ها رو ببین. همه‌ی تیکت‌ها رو یه بار بخون.
2. **اولویت‌بندی کن.** کدوم‌ها روی پول و اعتماد کاربر اثر دارن؟ کدوم‌ها سریع حل می‌شن؟ ترتیبت رو بنویس.
3. اگه روی یه تیکت بیشتر از ۱۵ دقیقه گیر کردی، یادداشت بذار و برو بعدی.
4. **۱۰ دقیقه‌ی آخر فقط برای `REPORT.md`.**

## چیزی که تحویل می‌دی
1. فایل `REPORT.md` پرشده
2. کدی که عوض کردی (یا `git diff`، اگه اولش `git init` و یه کامیت زدی؛ پیشنهاد می‌کنم بزنی)

## با چی سنجیده می‌شی
- اولویت‌بندی‌ت منطقی بود؟
- علت هر باگ رو درست و دقیق گفتی، یا فقط علامتش رو برطرف کردی؟
- فیکس‌هات جای درستی انجام شدن؟ (بعضی باگ‌ها جایی خودشون رو نشون می‌دن که علتشون اونجا نیست.)
- فیکس یه تیکت، چیز دیگه‌ای رو خراب نکرد؟
- از AI چطور استفاده کردی؟
- گزارش آخرت چقدر روشنه؟
